# Performance before/after — O5 (2026-09-30)

Measured with `node tools/perf.mjs` against `tools/router.php` (local PHP server: HTTP/1.1, **no gzip**,
so text weighs more than on Hostinger). Profile: 1.6 Mbps down / 150 ms RTT ("slow 4G", the Lighthouse mobile
network), CPU 4× slower at 390 px, cache disabled, third-party scripts blocked. Raw data:
`docs/perf/perf-before.json` (main @ 38dc39d) and `docs/perf/perf-after.json`.

## What changed

- **Critical CSS inline** (`<style>`, ~30 KB raw / ~7 KB gzip, the same for every page): rules of the components
  that can appear in the first screen (`CRITICAL_COMPONENTS` in `build.mjs`), extracted from `site.css` at build
  time by `tools/minify.mjs` (own code). The full stylesheet (`site.min.css`) loads non-blocking
  (`media="print"` + `onload`, `<noscript>` fallback). **Render-blocking requests: 1 → 0.**
- `tools/browser-check.mjs` loads every page twice at 390 and 1366 (with and without the full stylesheet) and
  fails if anything in the first screen moves by more than 2 px. That keeps the critical list complete and
  guards against layout shift when the full CSS arrives.
- `<link rel="preload" as="image" imagesrcset imagesizes fetchpriority="high">` for the page's hero image.
- `vc-attribution.js` loads from `site.js` on `requestIdleCallback` (timeout 3 s) instead of a `<script>` tag.
- Build-time minification: `site.min.css`, `site.min.js`, and generated HTML without indentation. The sources
  (`site.css`, `site.js`) stay the files to edit; qa.mjs fails if a `.min` file is stale.
- Lazy images get `fetchpriority="low"`. This helps on HTTP/2 (Hostinger); it has no effect on the local HTTP/1.1 server.
- **Font subsetting: skipped.** No subsetting tool (fontTools/pyftsubset, glyphhanger) is available without adding
  project dependencies, and the WOFF2 files are already latin subsets.

## Reading the numbers

- **First contentful paint: about −60 % everywhere** (≈1.4 s → ≈0.55 s on slow 4G).
- **Pages whose LCP is text** (most service pages at 390, contact, calculator at 1366): LCP −55 to −65 %.
- **Pages whose LCP is the hero image, on slow 4G only:** +100 to +310 ms (mobile home 1.58 → 1.89 s, desagüe
  at 1366 1.45 → 1.67 s). The text now paints at 0.55 s, but the hero image downloads slower. With the first
  screen laid out early, the Barlow 800 font and the first lazy service-card image (170 KB) start while the hero
  is still loading. They share the throttled HTTP/1.1 pipe with it. On regular 4G the effect disappears and
  every page tested is faster.
- I tried two alternatives and rejected them. Loading the full CSS only after `load` saved ≈120 ms but left
  below-the-fold content unstyled for longer. Deferring Barlow 600/800 moved the H1s by up to 72 px (CLS), and
  the new check caught it.
- Next lever, if wanted: lighter card images. The 800 px service-card WebPs are 170–197 KB. Re-encode them
  (`tools/prepare-images.py`, needs Pillow) or add a 1600 px hero variant for 1366 px screens, where the
  desktop home LCP (≈4.7 s on slow 4G) is the 2000 px hero image.
